# Исправления — Leostryx 3.1.0 (Bugfix Reference)

Документ фиксирует **точные первопричины** и **способ исправления** багов,
исправленных в релизе **3.1.0**. Если какой-то из багов снова проявится —
сначала сверьтесь с этим документом.

---

## Баг 1. Уведомления подтверждения из шторки появлялись каждые несколько секунд

### Симптомы (жалоба пользователя)
- Приложение **открыто**, но каждые ~4–45 секунд из шторки приходит жёсткое
  уведомление с кнопками «Разрешить / Продолжить».
- Даже при настройке **«Не спрашивать»** (авто-режим) уведомления с
  подтверждением продолжали появляться.
- Завершение задачи агента тоже выводило уведомление с кнопками подтверждения.

### Первопричина (три источника)

**1. `com.agy.ru.AgyShade.notify(...)` — булев параметр `needsAction` полностью игнорировался**
- Файл: `app/classes.dex` → `com/agy/ru/AgyShade.java` (метод `notify(String, String, String, boolean)`).
- В smali (`AgyShade.smali`, метод `notify`) признак `Z` (p4) **перезаписывался
  строкой `"title"`** на первой же строке — т.е. до проверки, и дальше
  **никак не использовался**.
- Кнопки «Ответить» и «Разрешить / Продолжить» добавлялись **всегда**, для любого
  уведомления, включая пассивные статусы.
- Канал `agy_agent_chat` создан с `IMPORTANCE_HIGH`, вибрацией и **без**
  `setOnlyAlertOnce` → каждое обновление уведомления снова «прыгало» шторкой.

**2. `patches/web_optimizations.js` → `nativeNotifications.send(opts)`**
- Строка `var needsAction = (...) || true;` — **всегда** `true`.
- Уведомления отправлялись **даже когда приложение на переднем плане**
  (`document.hidden === false`).
- События завершения `agent-finished-*` получали `payload.type === "request_action"`
  → тоже получали кнопки подтверждения.

**3. `agy_ru.js` → `checkAgentActivity()` (интервал 2 с)**
- Признак `b.dataset.agyNotified = "1"` вешался на DOM-кнопку. React
  **пересоздаёт** кнопку при ре-рендере → признак пропадал → через 4 секунды
  уведомление отправлялось снова для той же кнопки.
- Режим «Не спрашивать» (EAGER) не считывался.
- Пассивный прогресс отправлялся каждые 45 секунд, пока агент «работал».

### Исправление
**A. Java (`classes.dex`, smali-патч метода `notify`):**
- `.locals 9` → `.locals 10`; в начале: `move v9, p4` (сохраняем `needsAction`);
- `builder.setOnlyAlertOnce(true)` — после `setAutoCancel`;
- `if-eqz v9, :goto_skip_actions` перед построением кнопок → при
  `needsAction == false` кнопки **не добавляются** вовсе (чистое пассивное
  уведомление).

**B. `web_optimizations.js` → `nativeNotifications.send`:**
- `if (typeof document !== "undefined" && !document.hidden) return Promise.resolve();`
  — **никаких уведомлений, пока приложение открыто**;
- `needsAction` теперь вычисляется как:
  ```js
  var id = String(opts.id || "");
  var isFinished = id.indexOf("agent-finished-") === 0;
  var needsAction = !isFinished && !!opts.payload &&
    (opts.payload.needsAction === true || opts.payload.type === "request_action");
  ```
  → `agent-finished-*` всегда пассивные.

**C. `agy_ru.js` → `checkAgentActivity()`:**
- Добавлена `shieldAutoMode()` — читает `localStorage["agyShieldOv"]`,
  `term === 3` (EAGER «Не спрашивать») → в этом режиме approve-уведомления
  **никогда** не отправляются;
- Дедупликация по **тексту сниппета** (`lastApprovalSnippet`), а не по
  DOM-кнопке: одно и то же ожидающее подтверждение уведомляет **один раз**
  (повтор того же сниппета разрешён только через 5 минут);
- Как только кнопка подтверждения исчезла — `AgyShade.cancel("agent_approval")`
  (устаревшее уведомление убирается);
- Пассивное «Агент работает» — **один раз за запуск** (флаг
  `progressNotifiedThisRun`, сброс через 8 с после остановки), не каждые 45 с;
  в теле сообщения — **актуальный текст последнего шага агента** (что агент
  делает), взятый из DOM, либо фолбэк «Задача выполняется в фоне…».

### Как предотвратить регрессию
- Не возвращать `|| true` в `needsAction` в `web_optimizations.js`.
- Не удалять `move v9, p4` и проверку `if-eqz v9` в `AgyShade.smali` — без них
  кнопки снова появятся на пассивных уведомлениях.
- Не менять дедупликацию на базу `dataset` — React пересоздаёт DOM-кнопки.

## Баг 2. Фейковый чат с точкой на экране «Проекты» при переключении на кастомный провайдер

### Симптомы (жалоба пользователя)
- При переключении провайдера на кастомный (Настройки → Провайдеры) на экране
  проекта **на долю секунды появлялся ещё один чат** с точкой, показывающей,
  что «чат выполнил действие». Чат был фейковым и пропадал.

### Первопричина
- Переключение провайдера вызывает `AgyProviders.restartCore()` — ядро
  (CoreServerService) останавливается и стартует заново.
- При перезапуске восстановление потока `trajectorySummaries` приводит к
  проигрыванию событий завершения (`HDa`/`KDa` в `main.js`) → отправляется
  уведомление `agent-finished-*`.
- Раньше такие уведомления слались **даже при открытом приложении** и **с
  кнопками** — heads-up уведомление нависало над экраном «Проекты» и
  визуально выглядело как «ещё один чат с точкой» на доли секунды.
- Дополнительно `checkAgentActivity()` слал повторные уведомления, усиливая
  эффект.

### Исправление
- **Запрет отправки shade-уведомлений на переднем плане** (`!document.hidden`)
  в `web_optimizations.js` — при открытом приложении никаких «всплывающих
  чатов» поверх проекта;
- `agent-finished-*` стали **пассивными** (без кнопок), а при открытом
  приложении не отправляются вообще;
- Дедупликация в `checkAgentActivity()` исключила повторные появления.

### Как предотвратить регрессию
- Не убирать проверку `document.hidden` в `nativeNotifications.send` — это
  главный предохранитель «фейкового чата».
- Не возвращать `agent-finished-*` в список «требующих действия» событий.

## Баг 3. В селекторе моделей пропали разделители и названия провайдеров

### Симптомы (жалоба пользователя)
- В выпадающем списке моделей раньше были разделители и название провайдера
  перед его моделями; теперь «всё в кашу» — модели идут сплошным списком.

### Первопричины (комплексные)
1. **Кастомные модели (`RXb`) не имели атрибутов селектора**:
   - В `main.js` стандартные модели (`UXb`) рендерились с
     `data-testid="model-selector-item"` и `data-model-label={a.label}`.
   - Кастомные модели рендерились компонентом `RXb`, у которого не было ни
     `data-testid`, ни `data-model-label`. Поэтому `querySelectorAll('[data-testid="model-selector-item"]')`
     вообще **не находил** кастомные модели!
2. **Перезапись `__agyProviderSpecs`**:
   - `provider_model_groups.js` загружался синхронно раньше `agy_providers.js` и пытался
     обернуть `window.__agyProviderSpecs`. Но когда позже загружался `agy_providers.js`,
     он заново объявлял `window.__agyProviderSpecs = function() {...}` поверх патча,
     теряя поле `provider`.
3. **Отсутствие группировки в `SXb`**:
   - В `main.js` компонент `SXb` рендерил кастомные модели в плоский список без сортировки
     по провайдерам, под единственным заголовком «Custom».

### Исправление
- **В `agy_providers.js`**: `buildSpecs()` теперь напрямую проставляет `provider`, `providerName`
  и `providerType`, а также экспортирует `window.__agyGetProviderName(label)`.
- **В `main.js`**:
  - `RXb` получил `"data-testid":"model-selector-item"` и `"data-model-label":a.label`;
  - `cKa` прокидывает `providerName`;
  - `SXb` сортирует кастомные модели по имени провайдера (`__agySorted`).
- **В `provider_model_groups.js`**:
  - `getProviderName(label)` с тройным фолбэком (`__agyGetProviderName` → `specs` → парсинг `localStorage.agyProviders`);
  - Поиск элементов по `[data-testid="model-selector-item"]` и `.group.relative`;
  - Вставка стильных верхних разделителей (`agy-provider-separator`) с именем провайдера
    перед первой моделью каждого провайдера;
  - Идемпотентный ре-рендер по сигнатуре списка + интервал проверки.

### Как предотвратить регрессию
- Не удалять `data-testid="model-selector-item"` и `data-model-label` из `RXb`.
- Не полагаться на обезличенные monkey-patching функций, которые могут перезаписываться
  другими модулями — передавать метаданные в specs изначально.

## Баг 4. При запуске приложения логотип не акцентного цвета

### Симптомы (жалоба пользователя)
- При запуске приложения (на сплэш-скрине и на экране входа/запуска) логотип
  отображался в стандартных оранжево-кремовых тонах Рыси, а не в выбранном
  пользователем акцентном цвете.

### Первопричины
1. **`app/assets/web/brand/config.json`**:
   - Флаг `recolorLogo` отсутствовал (или был `false`).
2. **`tools/brand.py`**:
   - `recolorLogo` проверялся через `bool(cfg.get("recolorLogo", False))`. При значении `False`
     `splash_logo.png` и ресурсы APK собирались без тинтинга в акцентный цвет.
3. **`brand_logo.js`**:
   - В `getActiveBrand()` стоял фолбэк `recolorLogo: false`.
   - В `getLogoComp()` проверялся `typeof props.color === "string"`. Экран входа
     передавал `color: !0` (`color: true`), что не являлось строкой и игнорировалось,
     из-за чего `force` оставался `false` и тинтинг путей отключался.
4. **`theme-bootstrap.js`**:
   - При старте страницы применялись только `theme` (light/dark), но CSS-переменные
     акцента (`--primary`, `--accent`) не выставлялись до загрузки `agy_brand.js`
     в самом конце документа.

### Исправление
- **В `brand/config.json`**: выставлено `"recolorLogo": true`.
- **В `tools/brand.py`**: `recolorLogo` по умолчанию `True` → `splash_logo.png` тинтируется
  в акцентный цвет при сборке APK.
- **В `theme-bootstrap.js`**: добавлен мгновенный бутстрап акцентного цвета из
  `localStorage["agyBrandConfig"]` на `:root` до первой отрисовки страницы.
- **В `brand_logo.js`**: `getActiveBrand()` по умолчанию использует `recolorLogo: true`,
  а `getLogoComp()` распознаёт `props.color === true` и принудительно тинтирует логотип
  акцентным цветом бренда.
- **В `agy_brand.js`**: дефолт `recolorLogo: true`.

## Проверка после установки 3.1.0
1. Запустите приложение — **логотип сплэш-скрина и экрана входа отображается в акцентном цвете**.
2. Откройте селектор моделей — **кастомные модели сгруппированы по провайдерам с четкими разделителями и названиями провайдеров** (OpenAI, Claude, Gemini и т.д.).
3. Запустите агента в открытом приложении — **никаких уведомлений из шторки не появляется**.
4. Сверните приложение при активной задаче агента — приходит **одно** информационное уведомление с актуальным статусом шага (без кнопок подтверждения).
5. При включённом режиме «Не спрашивать» — при свёрнутом приложении уведомления с кнопками подтверждения не приходят вовсе.
6. Переключите провайдер — в окне проекта не появляется фейковых чатов или дублирующихся индикаторов.
