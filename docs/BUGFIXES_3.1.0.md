# Исправления — Leostryx 3.1.0 (Bugfix Reference)

Документ фиксирует **точные первопричины** и **способ исправления** багов,
исправленных в релизе **3.1.0**. Если какой-то из багов снова проявится —
сначала сверьтесь с этим документом.

---

## Баг 1. Уведомления подтверждения из шторки появлялись каждые несколько секунд

### Симптомы (жалоба пользователя)
- Приложение **открыто**, но каждые ~4–45 секунд из шторки приходит жёсткое
  уведомление с кнопками «Разрешить / Продолжить».
- Даже при настройке **«Не спрашивать»** (авто-режим) уведомления с
  подтверждением продолжали появляться.
- Завершение задачи агента тоже выводило уведомление с кнопками подтверждения.

### Первопричина (три источника)

**1. `com.agy.ru.AgyShade.notify(...)` — булев параметр `needsAction` полностью игнорировался**
- Файл: `app/classes.dex` → `com/agy/ru/AgyShade.java` (метод `notify(String, String, String, boolean)`).
- В smali (`AgyShade.smali`, метод `notify`) признак `Z` (p4) **перезаписывался
  строкой `"title"`** на первой же строке — т.е. до проверки, и дальше
  **никак не использовался**.
- Кнопки «Ответить» и «Разрешить / Продолжить» добавлялись **всегда**, для любого
  уведомления, включая пассивные статусы.
- Канал `agy_agent_chat` создан с `IMPORTANCE_HIGH`, вибрацией и **без**
  `setOnlyAlertOnce` → каждое обновление уведомления снова «прыгало» шторкой.

**2. `patches/web_optimizations.js` → `nativeNotifications.send(opts)`**
- Строка `var needsAction = (...) || true;` — **всегда** `true`.
- Уведомления отправлялись **даже когда приложение на переднем плане**
  (`document.hidden === false`).
- События завершения `agent-finished-*` получали `payload.type === "request_action"`
  → тоже получали кнопки подтверждения.

**3. `agy_ru.js` → `checkAgentActivity()` (интервал 2 с)**
- Признак `b.dataset.agyNotified = "1"` вешался на DOM-кнопку. React
  **пересоздаёт** кнопку при ре-рендере → признак пропадал → через 4 секунды
  уведомление отправлялось снова для той же кнопки.
- Режим «Не спрашивать» (EAGER) не считывался.
- Пассивный прогресс отправлялся каждые 45 секунд, пока агент «работал».

### Исправление
**A. Java (`classes.dex`, smali-патч метода `notify`):**
- `.locals 9` → `.locals 10`; в начале: `move v9, p4` (сохраняем `needsAction`);
- `builder.setOnlyAlertOnce(true)` — после `setAutoCancel`;
- `if-eqz v9, :goto_skip_actions` перед построением кнопок → при
  `needsAction == false` кнопки **не добавляются** вовсе (чистое пассивное
  уведомление).

**B. `web_optimizations.js` → `nativeNotifications.send`:**
- `if (typeof document !== "undefined" && !document.hidden) return Promise.resolve();`
  — **никаких уведомлений, пока приложение открыто**;
- `needsAction` теперь вычисляется как:
  ```js
  var id = String(opts.id || "");
  var isFinished = id.indexOf("agent-finished-") === 0;
  var needsAction = !isFinished && !!opts.payload &&
    (opts.payload.needsAction === true || opts.payload.type === "request_action");
  ```
  → `agent-finished-*` всегда пассивные.

**C. `agy_ru.js` → `checkAgentActivity()`:**
- Добавлена `shieldAutoMode()` — читает `localStorage["agyShieldOv"]`,
  `term === 3` (EAGER «Не спрашивать») → в этом режиме approve-уведомления
  **никогда** не отправляются;
- Дедупликация по **тексту сниппета** (`lastApprovalSnippet`), а не по
  DOM-кнопке: одно и то же ожидающее подтверждение уведомляет **один раз**
  (повтор того же сниппета разрешён только через 5 минут);
- Как только кнопка подтверждения исчезла — `AgyShade.cancel("agent_approval")`
  (устаревшее уведомление убирается);
- Пассивное «Агент работает» — **один раз за запуск** (флаг
  `progressNotifiedThisRun`, сброс через 8 с после остановки), не каждые 45 с;
  в теле сообщения — **актуальный текст последнего шага агента** (что агент
  делает), взятый из DOM, либо фолбэк «Задача выполняется в фоне…».

### Как предотвратить регрессию
- Не возвращать `|| true` в `needsAction` в `web_optimizations.js`.
- Не удалять `move v9, p4` и проверку `if-eqz v9` в `AgyShade.smali` — без них
  кнопки снова появятся на пассивных уведомлениях.
- Не менять дедупликацию на базу `dataset` — React пересоздаёт DOM-кнопки.

## Баг 2. Фейковый чат с точкой на экране «Проекты» при переключении на кастомный провайдер

### Симптомы (жалоба пользователя)
- При переключении провайдера на кастомный (Настройки → Провайдеры) на экране
  проекта **на долю секунды появлялся ещё один чат** с точкой, показывающей,
  что «чат выполнил действие». Чат был фейковым и пропадал.

### Первопричина
- Переключение провайдера вызывает `AgyProviders.restartCore()` — ядро
  (CoreServerService) останавливается и стартует заново.
- При перезапуске восстановление потока `trajectorySummaries` приводит к
  проигрыванию событий завершения (`HDa`/`KDa` в `main.js`) → отправляется
  уведомление `agent-finished-*`.
- Раньше такие уведомления слались **даже при открытом приложении** и **с
  кнопками** — heads-up уведомление нависало над экраном «Проекты» и
  визуально выглядело как «ещё один чат с точкой» на доли секунды.
- Дополнительно `checkAgentActivity()` слал повторные уведомления, усиливая
  эффект.

### Исправление
- **Запрет отправки shade-уведомлений на переднем плане** (`!document.hidden`)
  в `web_optimizations.js` — при открытом приложении никаких «всплывающих
  чатов» поверх проекта;
- `agent-finished-*` стали **пассивными** (без кнопок), а при открытом
  приложении не отправляются вообще;
- Дедупликация в `checkAgentActivity()` исключила повторные появления.

### Как предотвратить регрессию
- Не убирать проверку `document.hidden` в `nativeNotifications.send` — это
  главный предохранитель «фейкового чата».
- Не возвращать `agent-finished-*` в список «требующих действия» событий.

## Баг 3. В селекторе моделей пропали разделители и названия провайдеров

### Симптомы (жалоба пользователя)
- В выпадающем списке моделей раньше были разделители и название провайдера
  перед его моделями; теперь «всё в кашу» — модели идут сплошным списком.

### Первопричины (комплексные)
1. **Кастомные модели (`RXb`) не имели атрибутов селектора**:
   - В `main.js` стандартные модели (`UXb`) рендерились с
     `data-testid="model-selector-item"` и `data-model-label={a.label}`.
   - Кастомные модели рендерились компонентом `RXb`, у которого не было ни
     `data-testid`, ни `data-model-label`. Поэтому `querySelectorAll('[data-testid="model-selector-item"]')`
     вообще **не находил** кастомные модели!
2. **Перезапись `__agyProviderSpecs`**:
   - `provider_model_groups.js` загружался синхронно раньше `agy_providers.js` и пытался
     обернуть `window.__agyProviderSpecs`. Но когда позже загружался `agy_providers.js`,
     он заново объявлял `window.__agyProviderSpecs = function() {...}` поверх патча,
     теряя поле `provider`.
3. **Отсутствие группировки в `SXb`**:
   - В `main.js` компонент `SXb` рендерил кастомные модели в плоский список без сортировки
     по провайдерам, под единственным заголовком «Custom».

### Исправление
- **В `agy_providers.js`**: `buildSpecs()` теперь напрямую проставляет `provider`, `providerName`
  и `providerType`, а также экспортирует `window.__agyGetProviderName(label)`.
- **В `main.js`**:
  - `RXb` получил `"data-testid":"model-selector-item"` и `"data-model-label":a.label`;
  - `cKa` прокидывает `providerName`;
  - `SXb` сортирует кастомные модели по имени провайдера (`__agySorted`).
- **В `provider_model_groups.js`**:
  - `getProviderName(label)` с тройным фолбэком (`__agyGetProviderName` → `specs` → парсинг `localStorage.agyProviders`);
  - Поиск элементов по `[data-testid="model-selector-item"]` и `.group.relative`;
  - Вставка стильных верхних разделителей (`agy-provider-separator`) с именем провайдера
    перед первой моделью каждого провайдера;
  - Идемпотентный ре-рендер по сигнатуре списка + интервал проверки.

### Как предотвратить регрессию
- Не удалять `data-testid="model-selector-item"` и `data-model-label` из `RXb`.
- Не полагаться на обезличенные monkey-patching функций, которые могут перезаписываться
  другими модулями — передавать метаданные в specs изначально.

## Баг 4. При запуске приложения логотип не акцентного цвета

### Симптомы (жалоба пользователя)
- При запуске приложения (на сплэш-скрине и на экране входа/запуска) логотип
  отображался в стандартных оранжево-кремовых тонах Рыси, а не в выбранном
  пользователем акцентном цвете.

### Первопричины
1. **`app/assets/web/brand/config.json`**:
   - Флаг `recolorLogo` отсутствовал (или был `false`).
2. **`tools/brand.py`**:
   - `recolorLogo` проверялся через `bool(cfg.get("recolorLogo", False))`. При значении `False`
     `splash_logo.png` и ресурсы APK собирались без тинтинга в акцентный цвет.
3. **`brand_logo.js`**:
   - В `getActiveBrand()` стоял фолбэк `recolorLogo: false`.
   - В `getLogoComp()` проверялся `typeof props.color === "string"`. Экран входа
     передавал `color: !0` (`color: true`), что не являлось строкой и игнорировалось,
     из-за чего `force` оставался `false` и тинтинг путей отключался.
4. **`theme-bootstrap.js`**:
   - При старте страницы применялись только `theme` (light/dark), но CSS-переменные
     акцента (`--primary`, `--accent`) не выставлялись до загрузки `agy_brand.js`
     в самом конце документа.

### Исправление
- **В `brand/config.json`**: выставлено `"recolorLogo": true`.
- **В `tools/brand.py`**: `recolorLogo` по умолчанию `True` → `splash_logo.png` тинтируется
  в акцентный цвет при сборке APK.
- **В `theme-bootstrap.js`**: добавлен мгновенный бутстрап акцентного цвета из
  `localStorage["agyBrandConfig"]` на `:root` до первой отрисовки страницы (дефолт `#ec4899`).
- **В `brand_logo.js`**: `getActiveBrand()` по умолчанию использует `recolorLogo: true` и цвет `#ec4899`,
  а `getLogoComp()` распознаёт `props.color === true` и принудительно тинтирует логотип
  акцентным цветом бренда.
- **В `agy_brand.js`**: дефолт `recolorLogo: true`.
- **В `tools/brand.py`**: `load_brand()` динамически считывает активную конфигурацию бренда из
  `$HOME/web/brand/config.json` пользователя, дефолт `#ec4899`, генерирует розовый
  `res/drawable-nodpi-v4/splash_logo.png` и синхронизирует `app/assets/web/brand/config.json`.
- **В `agy_tools.sh` (`op_brand`)**: выбор цвета в настройках сохраняется как в `$HOME/web/brand/config.json`,
  так и в репозиторий проекта для последующих сборок.
- **В `agy_ru.js`**: полностью удалено лишнее пассивное уведомление `agent_progress` («Leostryx — Агент работает /
  Задача выполняется в фоне…»), так как в шторке уже активен статус ядра «Leostryx core running». Добавлена
  мгновенная отмена зависших уведомлений прогресса при активности в приложении.

## Баг 5. В светлых темах прозрачности не видно вообще

### Симптомы (жалоба пользователя)
- В тёмных темах стекло выглядело прозрачным, в светлых — как плотный белый пластик:
  «Прозрачность в темной теме меньше стала, в светлое вообще нет».
- Снижение альфы до 0.38 в светлой теме визуально ничего не меняло.

### Первопричина
Поверхность светлого стекла была **чисто белой** (`rgba(255, 255, 255, α)`), а страница под
ней — тоже белая. Композитинг белого цвета с любой альфой над белым фоном даёт тот же
белый пиксель: формула `C = α·255 + (1-α)·255 = 255` не зависит от α. Прозрачность
физически не могла проявиться, пока оттенок стекла совпадал с фоном.

### Исправление (финальная рецептура 3.1.0)
- **`agy_ru.js` → `updateGlassTheme()`**: цвет поверхности — **ровно `--background`
  активной темы**, БЕЗ подмешивания `--primary`. Подмешивание акцента (10–12 %) давало
  грязноватый оттенок, не совпадающий с фоном: у Monokai уходило в оливковый, у Dracula —
  в фиолетовый. `--primary` остаётся только в рамке, ховере, активном состоянии и тени.
- Светлая тема: тот же `--background`, **затемнённый на 12 %** (`rgb = bg · 0.88`).
  Именно затемнение, а не альфа, делает прозрачность видимой — см. первопричину выше.
- Альфа: **тёмная 0.88, светлая 0.72** (тёмная — исторически «идеальная» плотность из
  `5b11fa0`/`ef2aa78`; светлая — «лёгкая дымка» вместо прежних 0.92/0.38/0.58/0.64).
  Промежуточные 0.62/0.64 оказались слишком прозрачными для тёмной темы и не давали
  видимого эффекта в светлой.
- **`agy_ru.css`**: фолбэки `--agy-glass-surface` приведены к тем же числам
  (`color-mix(--background 88%)` и `color-mix(--background 88% #000 → 72%)`), чтобы стекло
  не вспыхивало другим цветом до первого кадра JS.
- `backdrop-filter` остаётся `none !important` — требование «чистая прозрачность без
  размытия», blur не возвращать.
- Та же рецептура применяется к `--popover`, поэтому меню, селекторы и нижние шторки
  выглядят одинаково.

### Как предотвратить регрессию
- Проверять прозрачность **только в светлой теме**: если изменили альфу, но не оттенок —
  эффекта не будет. Светлое стекло обязано быть темнее страницы минимум на 12 %.
- Тёмная тема: 0.88 — эталон. Не поднимать выше 0.92 (стекло становится глухим) и не
  опускать ниже 0.78 (появляется «дымка», жалобы на потерю плотности).
- В поверхность **не подмешивать `--primary`**: оттенок стекла должен совпадать с
  `--background`, иначе панели перестают выглядеть частью темы.
- Значения в JS и в CSS-фолбэке держать синхронными — рассинхрон даёт вспышку другого
  оттенка на старте.

## Баг 6. Кнопка «Медиа» открывала проводник с задержкой в несколько секунд

### Симптомы (жалоба пользователя)
- «Задержка при входе в файловый менеджер, через кнопку медиа не убрана. А если выбирать
  папку проекта, по кнопке "Папка" — мгновенно открывает файловый менеджер».

### Первопричина
`MainActivity.onShowFileChooser` (smali `com/agy/ui/MainActivity.smali`, ~строка 1803)
запускал `android.intent.action.GET_CONTENT` с MIME `*/*`. `GET_CONTENT` — это **запрос
контента**, а не файловый диалог: система сначала строит и показывает промежуточный
выбор приложения-источника, и только затем открывает DocumentsUI. Кнопка «Папка»
использует `OPEN_DOCUMENT_TREE`, который идёт в DocumentsUI напрямую — отсюда разница
«мгновенно против нескольких секунд».

### Исправление
- Строка action заменена на `android.intent.action.OPEN_DOCUMENT` в `app/classes.dex`.
- `onActivityResult` уже умел читать и `ClipData`, и `getData()`/`getDataString()`,
  поэтому правка не потребовала изменений в обработке результата.
- Побочный эффект: `takePersistableUriPermission(uri, 1)` теперь легален — постоянные
  разрешения выдаются только для URI, полученных через `OPEN_DOCUMENT`. Раньше вызов был
  формально некорректным для `GET_CONTENT`.
- Проверено декомпиляцией: `diff -rq` между smali оригинального и пропатченного APK
  показывает единственное различие — `com/agy/ui/MainActivity.smali`.

### Вторая причина (найдена после установки): `accept` из ~50 MIME-типов
Первой правки оказалось недостаточно. Жалоба повторилась, и при разборе
`generated/main.js` выяснилось: скрытый `<input type="file">` композера получал
`accept={PYb}`, а `PYb` — строка из ~50 расширений и MIME-типов
(`.png,…,audio/l16,audio/webm,.zip,…`), собираемая ещё и динамически из
`Object.keys(sB)` и `rB`. Перед вызовом `onShowFileChooser` WebView обязан
разрешить весь список (построение MIME-фильтров для ContentProvider), и только
потом отдаёт интент системе. Нативный код при этом `accept` **игнорирует** и
всегда ставит `setType("*/*")` + `ALLOW_MULTIPLE`, то есть список был чистым
оверхедом без единого полезного эффекта.

Кнопка «Папка» (`attachPickedFolder` → `j5a()`) создаёт **голый**
`<input webkitdirectory>` без `accept` — поэтому проводник открывался мгновенно.

### Исправление
- `var PYb=[…].join();` → `var PYb="*/*";` в `app/assets/web/generated/main.js`.
  Поведение не меняется (нативный слой и раньше открывал `*/*`), но исчезает
  разбор 50 типов. Заодно убирается вычисление массива на старте.
- Страховка в `agy_ru.js` (3.1.0): клик по пункту «Медиа» **не перехватывается**.
  Обработчик только проверяет `accept` у input композера и, если список снова
  окажется длинным (> 40 символов), схлопывает его до wildcard-MIME. Диалог
  открывает сам React через `input.click()`.
- Прежняя «страховка» с собственным голым пикером и пересылкой файлов через
  `DataTransfer` + `change` **удалена**: она вызывала `preventDefault()` /
  `stopPropagation()`, то есть отменяла `onClick` React. Если синтетический путь
  по любой причине не срабатывал, диалог не открывался вообще — это хуже
  задержки, которую он пытался убрать.
- Порядок в обработчике пункта меню исправлен: `{u.onClick(); m()}` — сначала
  открывается диалог, потом закрывается меню (раньше меню успевало убрать
  React-поддерево до `input.click()`).

### Как предотвратить регрессию
- Для выбора файлов использовать только `OPEN_DOCUMENT` / `OPEN_DOCUMENT_TREE`;
  `GET_CONTENT` добавляет лишний шаг выбора приложения.
- Не возвращать длинный `accept`: нативный слой всё равно открывает `*/*`,
  так что список только тормозит запуск и вводит в заблуждение.
- **Не подменять жест пользователя.** Никаких `preventDefault()` /
  `stopPropagation()` на клике по «Медиа»/«Папка»: `input.click()` обязан
  вызываться из того же жеста, иначе WebView теряет право открыть диалог.
  Это же причина, по которой `pointerdown`-обработчик в `agy_ru.js` пропускает
  `^(Media|Медиа|Folder|Папка)$` без blur.
- Проверять обе кнопки: «Медиа» и «Папка» должны открывать DocumentsUI за
  одинаковое время (обе идут через `OPEN_DOCUMENT`).

## Баг 7. Сессия обрывается, если уйти в фон или заблокировать экран

### Симптомы (жалоба пользователя)
- «Если в фоне или блокируется экран, то сессия обрывается» — активный чат переставал
  получать ответы, а после разблокировки оставался мёртвым.

### Первопричины (четыре независимых)
1. **Doze стартует сразу при гашении экрана.** На MIUI/HyperOS
   `dumpsys power` показывает `mDozeAfterScreenOff=true`. Doze блокирует приложению
   **сеть**, поэтому поток `core ↔ gateway` рвётся, хотя CPU не спит.
2. **Пакета нет в исключениях энергосбережения.** `dumpsys deviceidle whitelist` не
   содержал `com.agyru.t2` — система не считала приложение активным исключением.
3. **Стрим-хелпер `$i` (`main.js`) ретраит раз в 1000 мс, но таймер троттлится**
   в скрытой странице, поэтому восстановление откладывалось на неопределённый срок.
4. **Silent-media keep-alive умирает.** `agy_ru.js` держит беззвучный `bgAudio` при
   `document.hidden`, чтобы страница не засыпала, но после гашения экрана система
   сносит медиа-сессию — следующий уход в фон оставался без защиты.
   При этом `AppLifecycle.pause()` и `WebViewLifecycle.pause()` — пустые no-op, то есть
   нативная сторона WebView не приостанавливает: проблема именно в потере сети.

### Исправление
- **`agy_ru.js`**: добавлен `recoverAfterBackground()`, подписанный на
  `window.addEventListener("agy:host-resume", …)` (событие диспатчится из
  `WebViewLifecycle.resume()`) и `document.addEventListener("resume", …)`:
  перезапускает `startKeepAlive()` если чат выполняется и диспатчит синтетический
  `online`, чтобы `$i` сделал немедленный ретрай вместо ожидания тика.
- **`agy_tools.sh`**: новая операция `power` (`op_power`). Ищет `rish` в
  `$PREFIX/bin`, `$HOME/usr/bin`, `command -v`; проверяет
  `dumpsys deviceidle whitelist | grep -c $pkg`; при отсутствии выполняет
  `cmd deviceidle whitelist +$pkg` и перепроверяет. Печатает машиночитаемые строки
  `@@power pkg=… whitelisted=yes|no|no-rish` и `@@power mDozeAfterScreenOff=…`
  (через `timeout`, чтобы не подвесить job при отсутствии Shizuku).
- **`agy_ru.js`**, IIFE `ensurePowerExemption()`: вызывает `AgyTools.start("power","")`
  не чаще одного раза в 6 часов (`localStorage["agyPowerExemptCheck"]`), опрашивает
  `AgyTools.read(job)` каждые 700 мс до 20 попыток и пишет `console.warn`, если
  в логе `whitelisted=no`. Никаких диалогов и новых экранов — только лог.

### Как предотвратить регрессию
- Не добавлять `blur`/`pause`-логику в `AppLifecycle` — методы намеренно пустые.
- Не превращать `power` в UI-поток: он должен оставаться тихим и идемпотентным.
- Если менять `op_power`, помнить про `set -u` в начале `agy_tools.sh`: обращение к
  `$PREFIX` допустимо (его выставляет мост `AgyTools.start`), но новые переменные
  объявлять через `local`.

## Баг 8. Чип `/browser` в поле ввода нельзя удалить

### Симптомы (жалоба пользователя)
- «`/browser` прибит намертво: как обычный текст из окна контекста чата его не удалить».

### Первопричина
`/browser` вставляется не текстом, а узлом Lexical `beautifulMention`
(`qWa` → `vJ("/","browser",…)` + `aG(" ")`): внутри contenteditable это
inline-декоратор (`uJ extends SI`, `isInline() → true`). Декоратор не является
текстом, поэтому нативный Backspace рядом с ним либо выделяет его, либо не
делает ничего — в зависимости от позиции каретки, которую на телефоне ещё нужно
попасть пальцем.

### Исправление
- В `agy_ru.js` добавлен перехват клика по чипу
  (`[data-beautiful-mention], [data-lexical-beautiful-mention]`) внутри
  `contenteditable`:
  1. удаление через API самого Lexical — `root.__lexicalEditor` →
     `editor.update()` → поиск узлов `beautifulMention` с тем же текстом →
     `node.remove()`;
  2. если API недоступен — каретка ставится сразу после чипа и в редактор
     отправляется синтетический `Backspace` (обработчик Lexical не проверяет
     `isTrusted`), с повтором через 130 мс.
- После удаления фокус возвращается в поле ввода.

### Как предотвратить регрессию
- Чипы контекста — это узлы Lexical, а не DOM-текст: любые правки только через
  `editor.update()`, не через прямое удаление DOM-узла.

## Баг 9. Поле ввода не получало фокус после действия или вложения

### Симптомы (жалоба пользователя)
- После выбора «Упоминания» / «Действия» / «Браузер» и после прикрепления файла
  клавиатура не открывалась, приходилось тапать по полю ещё раз.

### Первопричина
Защита от ложного открытия клавиатуры (`guard`) снимала блокировку при
появлении вложения, но **не возвращала фокус**. А чипы действий вставляются
программно, поэтому фокус оставался на закрывшемся меню.

### Исправление
- `focusEditor()` в `agy_ru.js`: ставит фокус на `[contenteditable='true']`
  внутри `[data-testid='agent-input-box']`, предварительно сбрасывая `guard`.
- Вызывается из `MutationObserver` при появлении `[data-testid='input-attachment']`
  (через 120 мс, чтобы React успел отрисовать строку вложения) и через 140 мс
  после клика по пунктам Mentions / Actions / Browser.
- Кнопки `+`, селектор модели, щит и микрофон по-прежнему **не** открывают
  клавиатуру — правила `guard` не менялись.

## Проверка после установки 3.1.0
1. Запустите приложение — **нативный сплэш-скрин ОС Android и экран входа окрашены в акцентный розовый цвет (`#ec4899`)**.
2. Откройте селектор моделей — **кастомные модели сгруппированы по провайдерам с четкими разделителями и названиями провайдеров** (OpenAI, Claude, Gemini и т.д.).
3. Запустите агента — **в шторке нет лишнего уведомления «Leostryx — Агент работает»** (остаётся только штатный сервис «Core running»).
4. При включённом режиме «Не спрашивать» — при свёрнутом приложении уведомления с кнопками подтверждения не приходят вовсе.
5. Переключите провайдер — в окне проекта не появляется фейковых чатов или дублирующихся индикаторов.
6. Включите светлую тему и откройте любое выпадающее меню — **под стеклом виден контент страницы** (не глухой белый прямоугольник), размытия нет.
7. Нажмите «+» → «Медиа» — **файловый менеджер открывается сразу**, без промежуточного выбора приложения.
8. Запустите агента, сверните приложение и заблокируйте экран на минуту-две — после разблокировки **ответ продолжает приходить**, сессия не обрывается.
9. Проверьте исключение из Doze: `rish -c "dumpsys deviceidle whitelist | grep agyru"` должен вернуть строку с `com.agyru.t2`.
10. Вставьте `/browser` (или упоминание файла через `@`) и **тапните по чипу** — чип исчезает, каретка остаётся в поле ввода.
11. Прикрепите файл через «+» → «Медиа» — **клавиатура открывается сама**, как и после выбора «Упоминания» / «Действия» / «Браузер». Кнопки «+», селектор модели, щит и микрофон клавиатуру по-прежнему не открывают.
12. Переключите тему (Monokai → Dracula → Catppuccin → Light) и откройте любое меню — **оттенок стекла меняется вместе с темой**, размытия нет, под попапом виден контент.
13. Откройте Настройки и раскройте выпадающий список (например «Профиль безопасности») — ширина, отступы и скругления остались штатными Base UI, без обрезки текста и вылетов за экран.
